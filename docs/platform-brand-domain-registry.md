## Purchase discipline
1. Do not purchase solely from this document; verify registrar availability immediately before purchase.
2. Perform trademark/legal clearance before public launch.
3. Prefer the .com as canonical when obtainable; .app is useful for application branding; .social is defensive/semantic.
4. Do not create seven separate backends initially. Use one BuildPulse identity/social core with domain-aware branding until a product requires isolation.
5. Never advertise private chat as universally untraceable. Use audited E2EE and publish a precise privacy/retention model.
6. Agent/robot identities must remain visibly automated and controller-attributed.
